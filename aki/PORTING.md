# Porting libultragui to aki: the contract

`ugui/` (C++20) has been ported to aki, module by module, behavior for
behavior (the overview is [README.md](README.md)). This file is the contract
every porting agent works to: where each
C++ file goes, how C++ idioms map to the aki types chosen here, every seam
with its signature, the commands, and the compiler limits found so far. Read
it before writing a module; when you decide something the next module will
depend on, write it down here in the same commit.

## Layout and commands


Backends and optional subsystems are their own packages beside `ultragui/`,
each depending on it (and on the shared bindings they need):

```
  ultragui_glfw/         GlfwPlatform; src/sys/glfw.aki, the GLFW binding any

  ultragui_vulkan/       VulkanRhi, VulkanBackend (ugui_impl_vulkan);
                         src/sys/vulkan.aki generated by tools/gen_vk_binding.py
                         (also the binding ultragui_d3d12 presents through),
                         shaders/*.spv for the embed_shaders feature,
                         examples/{rhi_scene,embed_scene} (aki + C++ twins)
```

`ultragui_opengl`, `ultragui_d3d11` (including the Win32 input backend),
`ultragui_d3d12`, `ultragui_lua` (+ `ultragui_lua_lottie`, `ultragui_lua_video`),
`ultragui_lottie`, `ultragui_video` and `ultragui_audio` are described in
the tree above. There is no `ultragui_win32` package.

**Test support**: `ultragui_testing` (`Expect`, the failure counter most tests
use; `Suite`/`check`, the C++ tests' TEST/ASSERT shape) and `ultragui_scenes`
(the GL/D3D11 scene) are `[dev-dependencies]` of the packages that use them;
`ultragui_lua::test_harness` is the Lua tests' widget printer and output
capture. A test imports them by module name
(`import {Expect} from ultragui_testing::expect;`); what stays in a package's
`tests/support/` is specific to it. The recording `Rhi`/`TextureBackend`/
`AudioBackend` fakes in the tests record different things on purpose and stay
in the test that checks them.

All commands run in the repository's dev shell (it supplies clang, FreeType,
HarfBuzz and libstdc++, and puts them on `LD_LIBRARY_PATH` for programs akiko
builds; "Git tree is dirty" is harmless):

```
nix develop -c bash -c 'cd aki/ultragui && akiko check'          # package + tests
nix develop -c bash -c 'cd aki/ultragui && akiko test'           # build and run tests/*_test.aki
nix develop -c bash -c 'cd aki/ultragui && akiko test tests/world_test.aki'
nix develop -c bash -c 'cd aki/ultragui && akiko check --target x86_64-w64-windows-gnu'  # Windows layouts
aki/tools/test_all.sh                                            # all of the above for every package, windowed tests under Xvfb
aki/tools/test_xvfb.sh ultragui_d3d12                            # one package's tests with a software GPU and display
```

`test_all.sh` checks (`akiko check`, and `--target x86_64-w64-windows-gnu`,
which every package passes) and tests every directory under `aki/` with an
`aki.toml` and prints a summary; logs are in `/tmp/aki-test-all`. Windowed tests
skip without a display; under it they run on Mesa's lavapipe (Vulkan, and
through it DXVK-native and vkd3d) and llvmpipe (GL).

The C++ reference library and its tests:

```
nix develop -c bash -c 'cmake -S . -B /tmp/ugui-ref -G Ninja && ninja -C /tmp/ugui-ref && ctest --test-dir /tmp/ugui-ref'
```

Reference values for bit-exact tests come from `aki/ultragui/tools/gen_reference.cc`
(its header has the build line); Renderer2D's from `tools/gen_renderer_reference.cc`,
layout + paint's from `tools/gen_paint_reference.cc` (links a Release build of the
C++ library: at -O0 clang does not contract `a * b + c`, akiko always does). Extend it with a function per subsystem,
print one tagged line per value (`TAG a b c`, floats as `0x%08x` bits), and
paste the lines into the test as `static let` tables. The tables in
`core_test.aki` and `text_engine_test.aki` were recorded on aarch64 Linux.

The Lua packages' expectations come from `aki/ultragui_lua/tools/gen_lua_reference.cc`
(build line in its header; it needs Lua 5.4, which the dev shell supplies and
puts on `LD_LIBRARY_PATH`).

Commit early and in logical steps; a module, its test, and any contract
change here go together.

## Naming

- Types PascalCase (`TextEngine`, `WidgetId`); functions, methods and fields
  snake_case (`load_font`, `atlas_revision`); constants `kName`
  (`kInvalidFont`); enum variants without `k` (`FontWeight::Bold`).
- C++ accessor/mutator pairs keep their C++ field-style names
  (`master_volume()`, `set_master_volume()`).
- A field and a method may share a name; where that confuses, the field gets
  a trailing `_` (`atlas_texture_`).
- A constructor is a static function named after the type
  (`TextEngine()`, `World()`); several C++ constructors become named statics
  (`Rect::new`, `Rect::from_pos_size`, `EdgeInsets::all`).
- C++ overloads become distinct names: `LoadFont(path, weight, style)` is
  `load_font_styled`, `LoadFontMemory` is `load_font_memory`,
  `Lerp(Color...)` is `lerp_color`.
- Keywords that cannot be names: `null`, `loop` is fine but `looping` reads
  better for the audio flag. The module for rhi/null is `null_rhi`.
- Every module starts with a comment naming its C++ file(s) and every
  difference in shape (not in behavior) from the C++.

## Idiom map (the concrete types chosen)

| C++ | aki here |
|---|---|
| `Vector<T>` | `List<T>` (akikit::containers::list) |
| `String`, `const char*` text | `String`; parameters `str` |
| `const char* data, usize len` bytes | `bytes` (`&[byte]`); `&[u8]` for pixels the code computes on |
| `HashMap<K, V>` | `HashMap<K, V>` (akikit); iteration order never reaches output, as in the C++ (`sorted_entries`) |
| `Optional<T>`, nullable `T*` result | `T?`, `(&T)?`, `(&var T)?` |
| `bool F(..., T& out)` | `T?` or a tuple result |
| out-params `f32& w, f32& h` | tuple result `(f32, f32)` |
| `Function<R(A)>` member | `own fn(A): R` (e.g. `DragHandler = own fn(Vec2): ()`) |
| `Function` parameter called during the call | `fn(A): R` |
| C callback + `void* user_data` | a function value that captures |
| `UniquePtr<T>` | the value inline, `Box<T>`, or `T?` for "maybe constructed" |
| shared ownership | `Arc<T>` (TextRun shares its glyphs with the shaping cache) |
| `std::sort`/`IntroSort` | `intro_sort` (never akikit's sort: tie order differs) |
| `Min`/`Max`/`ClampMinMax` | `min`/`max`/`clamp_min_max` (+ `_f32` forms) |
| `std::from_chars` | `from_chars_f32`, `from_chars_u32` |
| enum class flags (`WidgetState`, `TextDecoration`) | `open enum` with `with`, `masked`, `without`, `has` |
| abstract interface swapped at link time | `capability` + a generic parameter with a default type |
| abstract interface supplied at run time | erased seam: capability + `Dyn<X><'a>` + `<X>Box` |
| `static` counters (NextWidgetId, WidgetRevision) | `static let` `Atomic<T>` |
| thread-local "active registry" | gone: pass the World |
| `assert(x)` the C++ relies on | `@stop` / `!` on the same condition |
| `static_cast<int>(float)` | `@saturating_cast` (what aarch64 does; UB in C++) |
| printf/fprintf logging | `println` / `eprintln` from akikit::logging, same text |

## Seams

Two kinds. **Link-time** C++ classes (one concrete class whose `.cc` is
swapped) are capabilities that UIContext is generic over, with a default
type. **Run-time** host-supplied virtual interfaces are erased seams: the
capability, a borrowed `Dyn<X><'a>` that core code takes where the C++ took
`X*`, and an owned `<X>Box` for an owner that keeps one. `core::erased`
(`ErasedRef<'a>`, `ErasedBox`) carries the object; each method is a
`static fn` thunk instantiated for the concrete type. The unsafe code lives
in `core::erased` and the thunks; the public API is safe. Copy
`render/texture_backend.aki` or `audio/audio_backend.aki` for a new one.

UIContext is `UIContext<P: Platform = HostPlatform, R: Rhi = NullRhi, S:
ScriptRuntime = NoScript>`; see "UIContext" below.

### Rhi (link-time) — `ultragui::rhi::rhi`

```aki
pub capability Rhi {
  fn init(var self&, config&: RhiConfig): bool;
  fn shutdown(var self&);
  fn begin_frame(var self&, clear_color: Color): bool;
  fn end_frame(var self&);
  fn set_scissor(var self&, rect: Rect);
  fn reset_scissor(var self&);
```

### World and components — `ultragui::widgets::widget_registry`, `core::component_store`

Component types are open. Each has a `ComponentKey<C>`, a `static let` beside
the type; the key's dense id (assigned process-wide on first use, as
ComponentTypeId is) indexes the World's stores, which are created on first
use and held erased with a remove thunk:

```aki
pub struct ButtonContent { ... }
pub static let kButtonContent: ComponentKey<ButtonContent> = ComponentKey();

var world = World();
let e = world.create();                       // New(): WidgetNode, Transform, StyleC, Hierarchy attached
world.add(kButtonContent, e, ButtonContent { ... });      // returns &var C; ignore it as a statement
if (let c& = world.get(kButtonContent, e)) { ... }        // (&C)?, none if absent or stale
if (var c& = world.get_var(kButtonContent, e)) { ... }    // (&var C)?
var s& = world.get_or_add(kStateStyle, e, StateStyle {}); // GetOrAdd: the fallback is the C++ C{}
let (t, h) = world.get_pair_var(kTransform, kHierarchy, e);  // two components at once
world.has(kTooltip, e); world.remove(kTooltip, e);
for (let id in world.store(kButtonContent)!.ids()) { ... }   // dense iteration: ids() / as_slice()
world.release(e);                              // drops every component; handles go stale
```

Host components work the same way, from any package; a component's drop is
its release notification. Keys: `kWidgetNode`, `kTransform`, `kHierarchy`,
`kStyleC` (widgets::widget); `kTooltip`, `kMovable`, `kDragHandle`,
`kStateStyle`, `kAnimStyle` (widgets::components). Each widget kind module
declares its own (`kTextContent`, `kButtonContent`, ...).

A view from `get`/`get_var`/`add` borrows the whole World (the C++ "valid
until the next structural change", enforced). Copy out what you need
(`Transform`, `StyleC`, `Style` are `Copy`; `to_list(h.children.as_slice())`
for a child list you walk while mutating), then call the next function.

There is no `WidgetRegistry::Active()`: every function that touches entities
takes `var world&: World` first. `WidgetRegistry` remains as an alias of
`World`.

### Renderer2D and the Rhi — `ultragui::render::renderer2d`

The API is the C++ one in snake_case (`draw_rect`, `draw_rect_gradient`,
`draw_shadow`, `draw_inset_shadow`, `draw_bordered_rect`, `draw_text`,
`draw_text_layout`, `draw_radial_gradient`, `draw_multi_stop_gradient`,
`draw_textured_rect`, `push_scissor`/`pop_scissor`,
`push_transform`/`pop_transform`, `set_next_blur`, `set_display_size`,
`get_draw_data`), same parameter order, C++ defaults as aki defaults. The one
parameter-shape exception: `GradientStop* stops, u32 count` is
`stops: &[GradientStop]` (`s.gradient_stops[..s.gradient_stop_count as usize]`).
Widget code takes `var renderer&: Renderer2D` (no lifetime, no type parameter).

Renderer2D is not generic over the Rhi and keeps no view of it. The C++
reads `rhi_->display_size()` and `rhi_->dpi_scale()` while drawing; here an
attached renderer keeps a snapshot of both, taken by `init_rhi` and refreshed
by `begin_frame_rhi` (nothing changes them between begin and end of a frame):

```aki
var r = Renderer2D();
r.init();                         // Init(nullptr): draw-data mode
r.set_display_size(viewport);
r.set_texture_backend(TextureBackendBox::of(host_textures));   // owned; none = flat gradients
r.begin_frame();  paint...;  let dd = r.get_draw_data();       // DrawData views r's buffers

r.init_rhi(rhi);                  // Init(&rhi): legacy mode
r.set_rhi_texture_backend();      // gradients through the Rhi (UIContext's RHITextureBackend)
r.begin_frame_rhi(rhi);  paint...;  r.end_frame(rhi);           // submits in emission order
```

Gradient textures: with a host backend (owned `TextureBackendBox`) they are
created at draw time, as in the C++. The legacy RHI adapter borrows the Rhi
its owner keeps, so the renderer cannot hold it; in Rhi-texture mode a new
gradient gets a provisional id (counting down from `kFontTextureId - 1`,
above anything an Rhi mints) and `end_frame(rhi)` (or
`resolve_textures(rhi)`, for a get_draw_data user) creates the pending
textures in request order and patches batches and cache before submitting.
Batching only compares ids, so the batches are the C++ ones
(renderer2d_test checks both modes against the C++). `texture_backend()`
lends the owned host backend to other subsystems (UIContext's
`texture_backend()` in draw-data mode).

### The layout engine — `ultragui::layout::{flex_style,flex_tree}`

The C++ lays out with yoga; the port has its own flexbox engine, so the core
package compiles no C++ and links no libstdc++. It is yoga (`third_party/yoga`
at 8c5ea16d) cut down to what layout.cc writes, and its contract is yoga's
results, bit for bit, on retained trees relaid out frame after frame:

```aki
var tree = FlexTree();
let n = tree.add_node();                                     // YGNodeNewWithConfig
tree.insert_child(parent, n, index);                         // YGNodeInsertChild
tree.set_measured(n);                                        // YGNodeSetMeasureFunc
tree.set_intrinsic(n, w, h);                                 // what the measure function reports
tree.mark_dirty(n);                                          // YGNodeMarkDirty
tree.set_dimension(n, kWidth, StyleLength::percent(50.0));   // YGNodeStyleSetWidthPercent: compares, stores, dirties
tree.set_margin(n, kTop, 4.0);                               // ... and the other YGNodeStyleSet* layout.cc calls
tree.calculate_layout(root, vw, vh);                         // YGNodeCalculateLayout(root, vw, vh, LTR)
tree.layout_left(n); tree.layout_width(n); tree.layout_margin(n, kTop); tree.layout_padding(n, kLeft);
```

**Scope.** Flex direction (all four), justify-content (flex-start, center,
flex-end, space-between/around/evenly), align-items/self/content (auto,
flex-start, center, flex-end, stretch, baseline without a baseline function,
space-*), wrap and wrap-reverse, overflow visible/hidden/scroll, position
relative/absolute with insets in points, display flex/none, grow, shrink,
basis (auto, points, percent), width/height (points, percent, auto), min/max
(points, percent, undefined), margins and padding per physical edge in points,
gaps (all/row/column, points or undefined), aspect ratio; a measure function
that reports a fixed intrinsic size whatever the constraints (libultragui's);
yoga's default config (point scale factor 1, pixel-grid rounding, no errata,
no experimental features). Not there, rather than stubbed: RTL, margin auto,
percent margins/padding/insets/gaps, borders, static position, display
contents, box-sizing content-box, the `flex` shorthand, baseline functions,
constraint-dependent measure functions, cloning, events, logging. A style
feature layout.cc starts writing must be added from yoga's code (and to the
oracle's copy of apply_style) before it is used.

**How it matches.** flex_tree follows yoga's CalculateLayout, AbsoluteLayout,
FlexLine, Cache, PixelGrid and Baseline step for step (each function names the
yoga one it ports) and keeps the state yoga carries between passes, because
yoga's incremental results are not those of a fresh layout: on the oracle's
trees about 23% of relayouts give a different left/top/width/height somewhere
than laying the same final tree out from scratch (the caches, the kept flex
basis and the style pool's history together; turning the caches off alone
changes 11,845 of 5.4 million result floats). So it has yoga's dirty flags (propagation stops at the first dirty
ancestor), its layout cache and eight measurement cache entries with their
tolerant, pixel-grid-rounded comparisons, the computed flex basis that only a
dirtied node forgets, the line index each child keeps (baseline alignment
reads it again), and rounding to the pixel grid only after a pass that laid
the root out, which rounds the already rounded positions of cached subtrees
again. Also kept on purpose:

- style values stored as yoga's StyleValuePool stores them: an integer from
  -2047 to 2047 is packed into the handle, so -0.0 reads back as +0.0 (a
  negative percent inset resolves to -0.0 in layout.cc), unless the slot has
  held a non-integer before, which makes it keep exact bits from then on;
  setters compare against what reads back (aspect ratio against the value as
  passed, before 0 and infinities become undefined);
- yoga's +0.0 borders are added where yoga adds them (`kBorder`): they turn a
  -0.0 padding into +0.0;
- the gap is counted for every child when checking for main-axis overflow,
  absolute and display: none ones included;
- multi-line align flex-start offsets a child by its inset, not its margin;
- display: none children of a wrap-reverse container get a NaN position (their
  measured size is NaN when the mirroring reads it);
- a single child that can both grow and shrink in an exactly sized line gets a
  flex basis of 0 without being measured;
- the two-pass flexible-length resolution, not the spec's loop.

**Floats.** akiko fuses a product into the add or subtract that takes it
inside one expression, and so does clang at its default `-ffp-contract=on`,
which the C++ library and the oracle are built with. So each yoga expression
keeps its shape here, and where yoga's add takes a conditional whose arm is a
product (stretched aspect-ratio children in STEP 7), the conditional goes into
a local first: clang never fuses through it, and the local keeps akiko from
it.

**Verification.** `tests/yoga_fuzz_test.aki` builds `tools/yoga_fuzz.cc` and
yoga with clang++ into `build/yoga_oracle/` (once; again when the tool is
newer) and plays 10 seeded chunks of 2000 trees: up to 40 nodes in depth-first
order as layout_tree numbers them, styles drawn at libultragui's level (px, %,
vw, vh, frac, auto, a ui scale, min 0 / max 1e6 meaning none, equal and
conflicting min/max) and written through a copy of layout.cc's apply_style,
measured leaves, absolute children, display: none leaves and a few with
children, every enum value, then up to six more passes of restyles,
re-measured leaves with MarkDirty, unchanged rewrites and viewport/scale
changes. 79,941 layouts, 18,196,740 result floats (left, top, width, height,
margins, paddings), all equal by their bits. `YOGA_FUZZ_SEED`,
`YOGA_FUZZ_CHUNKS` and `YOGA_FUZZ_TREES` change the run; a failing chunk's
trace is kept and the first differences are printed by tree, pass and node;
`akiko test tests/yoga_fuzz_test.aki -- trace...` replays recorded traces.
Breaking one reproduced behavior at a time (keeping the flex basis, the -0.0
packing, the sticky pool bit, the layout or measurement cache, the cache's

add (which clang's assembly confirms is not fused). The golden draw-data
comparison (tools/golden) stays 21/21 `same` on the engine.

### The shaper — `ultragui::shape`

The C++ library shapes with HarfBuzz on an hb_ft font. `ultragui::shape` is
an OpenType shaper in aki whose contract is HarfBuzz 13.2.1's output for
exactly the calls text_engine makes (`hb_buffer_add_utf8` of the whole text,
no context, `hb_buffer_guess_segment_properties`, `hb_shape` with no
features, the hb_ft font at FT_Set_Pixel_Sizes' size): glyph ids, clusters,
advances and offsets in 26.6, in HarfBuzz's order (right-to-left runs come
out reversed), bit for bit. It does not call FreeType or HarfBuzz.

```aki
var face = ShapeFace::from_bytes(font_bytes, 0, ft_num_glyphs);   // once per font; caches shape plans
let glyphs = shape(face, metrics, x_scale, y_scale, "Hello");     // List<ShapedGlyph>
// ShapedGlyph { glyph_id, cluster, x_advance, y_advance, x_offset, y_offset }
// shape_utf8(face, metrics, x_scale, y_scale, bytes) takes any bytes (ill-formed UTF-8 -> U+FFFD as HarfBuzz)
```

What the shaper needs from the font engine is the capability
`ShapeFontFuncs` (`shape::font_funcs`): `h_advance(gid)` (hb_ft's:
FT_Get_Advance with FT_LOAD_DEFAULT | FT_LOAD_NO_HINTING, then
`(int) ((float) abs (v) + 512.f) >> 10`) and `glyph_extents(gid)` (hb_ft's:
FT_Load_Glyph with the same flags, bearings and size through HarfBuzz's
`roundf`, which is `floorf (x + .5f)`), plus the font scale
`x_scale = (FT_Size_Metrics.x_scale * units_per_EM + 0x8000) >> 16` (and y)
and `ft_num_glyphs`, FreeType's `face->num_glyphs` (FT_Get_Char_Index rejects
glyph ids at or above it; for TrueType it is maxp's count, for CID-keyed CFF
the last CID + 1). hb_ft never sets the font's ppem, so device tables and
anchor contour points never apply and no contour-point function is needed.
Everything else (cmap, GSUB, GPOS, GDEF, kern) the shaper reads from the
font's bytes. tests/support/shape_ft.aki implements the capability on the
real FreeType for the test.

**Scope.** The whole hb_ot_shape pipeline: UTF-8 decoding with HarfBuzz's
replacement, Unicode properties (general category, combining classes and
HarfBuzz's modified classes, scripts, mirroring, decompositions and
compositions, default ignorables, Extended_Pictographic, Arabic joining
types, Indic and USE categories) generated from HarfBuzz's own tables;
script, direction and language guessing (the language is the C locale's,
"c", which maps to no OpenType language tag: the language system is 'dflt' or
the script's default); the cmap as FreeType selects and reads it (formats 0,
4 with its sorted/overlapping variants, 6, 12, 13, 14, FT_VALIDATE_DEFAULT,
the symbol-font fallbacks of hb_ft); grapheme clusters, native direction,
mirroring, normalization (decompose, reorder, recompose, variation
selectors, space fallbacks); the shape plan (hb_ot_map_builder_t: stages,
pauses, bit allocation, script/language selection with HarfBuzz's fallbacks,
feature variations at the default instance, required features); GDEF
classes (with HarfBuzz's blocklist) or synthesized ones, mark filtering sets
and attachment types; every GSUB (1-8) and GPOS (1-9) lookup type with
HarfBuzz's skippy-iterator, ligature-component and nested-lookup semantics;
the legacy kern table (format 0); fallback mark positioning, fallback spaces,
zero-width marks and default ignorables; and the script shapers: default,
Arabic (joining, stch, mark reordering, the fallback lookups synthesized from
presentation forms), Hebrew, Thai and Lao (with the PUA fallback), Hangul,
Indic (all nine scripts, old and new spec), Khmer, Myanmar and the Universal
Shaping Engine, their syllables found by HarfBuzz's own Ragel tables
(`tools/gen_shape_machines.py` extracts them and compiles their actions).

**Design.** `shape::buffer` is hb_buffer_t's in/out-buffer protocol with the
var1/var2 scratch values as named fields; `otl` reads tables in place
(offsets into the table bytes; a zero offset or a read past the end gives
HarfBuzz's all-zero Null object); `layout` is the apply context and every
subtable; `map`/`plan` build and cache plans per (script, direction) in the
face; `shapers` dispatches the shaper hooks and pause functions by shaper
number. Tables come from `tools/gen_shape_tables.cc`, which compiles
HarfBuzz 13.2.1's amalgamated source and dumps its Unicode and shaper data
(`tools/gen_shape_tables.py` packs it into `src/shape/data/ucd.bin`, 145 KB,
and `ucd_tables.aki`), and `tools/gen_shape_machines.py` (the syllable
machines and vowel constraints into `machines.aki`). Optimizations HarfBuzz
makes that cannot change the result are left out (set digests on the apply
path, subtable caches, the rule-set fast paths, glyph flags); the digest is
kept where it changes a result (`would_substitute`'s prefilter, which the
Indic shaper's consonant positions depend on).

**Verification.** `tests/shape_test.aki` builds `tools/shape_oracle.c`
(the dev shell's FreeType + HarfBuzz, used exactly as text_engine uses them)
into `build/shape_oracle/`, shapes the same strings with both and compares
every value. Strings: the quoted strings of `examples/**/*.ugui` and `*.lua`,
the per-script samples of `tests/support/shape_samples.aki` (Latin, Greek,
Cyrillic, Vietnamese, Hebrew, Arabic/Persian/Urdu, Syriac, Thaana, N'Ko, the
nine Indic scripts, Sinhala, Thai, Lao, Khmer, Myanmar, Tibetan, Hangul, CJK,
kana, Ethiopic, Armenian, Georgian, Cherokee, Mongolian, Javanese, Balinese,
Tai Tham, Chakma, emoji sequences, spaces, joiners, variation selectors) and
strings generated from each font's cmap (runs of its letters with marks,
other characters, digits, punctuation, spaces, ZWJ/ZWNJ/CGJ, variation
selectors and ill-formed UTF-8). Default run: DejaVuSans, NotoSansMono,
LiberationSans, NotoSansCJK (CFF, collection), KacstBook (Arabic),
Lohit-Devanagari, Garuda (Thai), KhmerOS, FreeSerif at 12, 16 and 24 px:
50,274 strings, 566,112 glyphs, all equal (about 8 s). `SHAPE_SWEEP=1` runs
every font of /usr/share/fonts at 9, 12, 16, 24 and 37 px with 400 generated
strings per font (`SHAPE_GENERATED`, `SHAPE_SEED`, `SHAPE_FONTS=a:b` change
it): SWEEP_RESULTS.

**Known gaps.** HarfBuzz is built with graphite2 here and shapes fonts with a
`Silf` table (Padauk, Abyssinica SIL, Annapurna SIL) with it; the aki shaper
shapes them with OpenType, so they differ and the test skips them. The
language is fixed to the C locale's (a program whose toolkit calls
`setlocale (LC_CTYPE, "")` before the first shape, as GLFW on X11 does, gives
HarfBuzz the environment's language, which can select another language
system). Not implemented (no font of the corpus needs them): AAT
(morx/kerx/trak), `kern` subtable formats 1-3 and Apple's kern table, the
24-bit ("beyond 64K") GSUB/GPOS/GDEF formats, cmap formats 2, 8 and 10 and
the Unicode charmap FreeType synthesizes for fonts without one, variation
coordinates other than the default instance, the Windows-1256 Arabic
fallback (Windows builds of HarfBuzz only), the Myanmar Zawgyi shaper
(script Qaag never comes from guessing). HarfBuzz's sanitizer, which neuters
offsets of malformed subtables, is approximated by reading out-of-range
data as zeros.

### InputRouter — `ultragui::input::input`

The router reaches the platform through `ctx.platform` (no `Init(Platform*)`;
UIContext points both at one platform, and `ctx.platform == none` is the C++
`!platform_`). Everything that touches widgets takes the World and the
context:

```aki
var router = InputRouter();
router.set_on_click(own fn(w: WidgetId, b: MouseButton) { ... });   // ClickHandler, HoverHandler,
router.register_shortcut(key, mods, own fn() { ... });              // ShortcutHandler, GamepadBackHandler
let consumed = router.process(world, ctx, root);
router.set_focus(world, ctx, e);  router.set_hover(world, ctx, e);
router.refresh_hover(world, ctx, root);  router.reset_state(world, ctx);
```

process copies the platform's queue (widget calls need the context, which
lends the platform) and clears the platform's queue at the end, as the C++
does. Handlers keep the C++ signatures and get no World: an application
handler that must reach widgets or the script runtime (the examples' Lua
`on_<name>` dispatch) records the widget and acts after process returns.

`widgets::scroll_view` exists as a stub (ScrollViewContent,
kScrollViewContent, scroll_offset) in a commit titled "stub scroll_view ...":
the widget-kinds port replaces the file.

### Widget dispatch — `ultragui::widgets::widget_vtable`

Per-kind behaviour is a `match` on `WidgetKind` per vtable entry, calling the
kind's functions directly:

```aki
pub fn vt_measure(kind: WidgetKind, var world&: World, var ctx&: WidgetContext, e: WidgetId): (f32, f32)? => match (kind) {
  WidgetKind::Button => button_measure(world, ctx, e),     // the arm a kind's port adds
  _ => none,                                               // the C++ null entry
};
```

Entries: `custom_paint`, `vt_draw` (bool: had an entry), `vt_measure`,
`vt_hit_test`, `vt_on_click`, `vt_on_update`, `vt_on_scroll`, `vt_on_layout`,
`vt_on_key_down`, `vt_on_char_input`, `vt_consumes_text_input`,
`vt_on_dismiss`. A kind function has the shape
`fn button_measure(var world&: World, var ctx&: WidgetContext, e: WidgetId): (f32, f32)`
(the C++ out-params as results). The free functions in widgets::widget
(`measure_widget`, `click_widget`, `hit_test`, `layout_widget`, ...) apply the
C++ fallbacks. A widget kind port: its module (content struct + key +
`create_<kind>` + entry functions), its arms here, its test.

Callbacks stored in components (`on_click`, `on_change`) are `own fn` values.
One that needs the World gets it as a parameter, not a capture; the caller
takes the callback out of the component (or copies what it needs) before
calling it, because the component's view borrows the World.

### Subsystems that held a backend pointer: LottieAnimation, VideoPlayer

The C++ `LottieAnimation` keeps the `TextureBackend*` it was loaded with and
`VideoPlayer` keeps the `RHI*`. A struct cannot hold a borrow of something its
own owner (UIContext) also owns, so the ported types hold neither: every
method that can render, upload or free takes the backend as an argument, the
way `TextEngine::flush_atlas(rhi)` does.

```aki
var anim = LottieAnimation();
var tex = DynTextureBackend::of(host_textures);       // or boxed.as_dyn(); null C++ pointer = `none`
anim.load(tex, "spinner.json", 64, 64);               // backend: (&var DynTextureBackend)?
anim.update(dt, tex);  anim.seek(0.5, tex);  anim.stop(tex);
anim.unload(tex);                                     // releases the texture; do this before drop

var vid = VideoPlayer();
vid.load(rhi, "cutscene.mpg", none);                  // rhi: var R (R: Rhi); audio: (&DynAudioBackend)?
vid.update(dt, rhi);  vid.convert_frame(rhi);  vid.seek(t, rhi);  vid.stop(rhi);
vid.unload(rhi);                                      // destroys Y/Cb/Cr and the render target
```

Pass the same backend/RHI the animation was loaded with. A drop without
`unload` frees the CPU side (rlottie animation, pl_mpeg decoder, audio device)
and leaves the GPU handles to the backend's own teardown. Methods that touch
neither (`play`, `pause`, `set_speed`, `is_playing`, `progress`, ...) take no
backend. UIContext's `LoadLottie`/`LoadVideo` are frame extensions in their
packages (see "UIContext"): the package's player list is a `UiExtension` that
gets the texture sink and the Rhi in its `FrameEnv` on each call:

```aki
let id = load_lottie(ui, "spinner.json", 128, 128)!;   // ultragui_lottie::lottie_ui; LottieId (index)
var a& = lottie_var(ui, id)!;  a.play();  a.set_loop(true);  let tex = a.texture();
lottie_stop(ui, id);  lottie_seek(ui, id, 0.5);       // through UIContext's texture sink
let v = load_video(ui, "demo.mpg")!;                   // ultragui_video::video_ui; VideoId
video_var(ui, v)!.play();  video_stop(ui, v);  video_seek(ui, v, 2.0);   // through UIContext's Rhi
```

The first load adds the extension (`LottiePlayers` / `VideoPlayers`, keys
`kLottiePlayers` / `kVideoPlayers`); add the Lottie one first when a program
uses both (`add_lottie_lua` before `add_video_lua` does), as the C++ updates
lottie_anims_ before video_players_.

* `ultragui_audio`: miniaudio is `[build.implement]` from `third_party`

### Widget callbacks — `ultragui::widgets::callbacks`

A C++ widget callback (`Function<void()>`, `Function<void(bool)>`, ...)
reached the widgets through `WidgetRegistry::Active()` and each widget's
context pointer. Here every widget callback takes a `CallbackEnv` first: the
World and the WidgetContext the event is dispatched with, lent for the call.

```aki
pub struct CallbackEnv<'w, 'a> { pub var world: &'w var World  pub var ctx: &'w var WidgetContext<'a> }
pub type Action = own fn(&var CallbackEnv): ();                  // Function<void()>
pub type BoolHandler = own fn(&var CallbackEnv, bool): ();       // checkbox / radio / toggle
pub type F32Handler = own fn(&var CallbackEnv, f32): ();         // slider
pub type TextHandler = own fn(&var CallbackEnv, String): ();     // text input change / submit (owned copy)
// per kind: DropdownChangeHandler (i32, String), HistoryHandler (): String,
// MessageBoxResultHandler (MessageBoxResult)

set_button_click(world, btn, own fn(env: &var CallbackEnv) {
  set_text(env.world, label, "clicked");                 // captures are Copy ids
  set_checked(env.world, env.ctx, box, true);
});
```

Calling one (every kind does it this way; copy it for a host component):
swap the handler out of its component inside an `if (var c& = world.get_var(..))`
block, call it with `var env = CallbackEnv { world, ctx };` in its own block,
then put it back if the component still exists and the slot is still empty
(a handler that installed a replacement keeps it; one that destroyed its
widget drops itself). The C++ runs the std::function in place, where both of
those are undefined. Text arguments are owned copies taken before the call.
The script runtime's `wire_change_handlers` builds these handlers; its Lua
call gets `env.world` and `env.ctx`.

### Backend packages: GLFW and Vulkan

`ultragui_glfw::platform_glfw::GlfwPlatform` is the Platform of

### ultragui_d3d12

`D3d12Rhi` (`pub struct D3d12Rhi : Rhi`) is d3d12_rhi.cc call for call: a D3D12
device from vkd3d (Linux has no DXGI), a Vulkan swapchain beside it whose
images are wrapped as D3D12 resources, and the same command sequence, barriers
and root signatures. `UIContext<P, D3d12Rhi, S>` where the C++ build links the
file. Notes for whoever builds on it:

* **COM**: `sys::d3d12` holds C-layout structs (every field defaults to zero,
  `ResourceDesc {}` is `D3D12_RESOURCE_DESC desc = {}`), the vkd3d entry points,
  and, between the GENERATED markers, `ID3D12*` objects as `extern struct`s that
  hold only the vtable pointer, their vtables (every slot, in order; the
  methods the port calls typed, the rest `*const u8`), IIDs (`pub static let
  kIid...`, `&raw kIidDevice`) and one `unsafe fn` wrapper per called method
  (`dev_create_fence`, `cl_draw_instanced`, `res_get_desc`: hidden struct results
  come back by value; `com_release(p)` is any object's Release). Add a method by
  naming it in `tools/gen_d3d12.py` (INTERFACES) and rerunning
  `python3 -I tools/gen_d3d12.py <vkd3d include dir> com`; `... layout` rewrites
  `tools/layout.c` and `tests/layout_test.aki`, which checks every struct's size,
  alignment and field offsets and every constant against the real headers. Types
  that clash with the core are `D3dRect`/`D3dBox`.
* **Shaders**: the C++ build compiles shaders/hlsl to DXIL and loads the .cso
  files from ULTRAGUI_HLSL_SHADER_DIR. The package embeds the same blobs
  (`shaders/*.cso`, byte-identical to the CMake output; `tools/build_shaders.sh`
  regenerates them). `RhiConfig::shader_dir` empty uses them; a directory loads
  `<dir>/{quad,text,video}_{vs,ps}.cso` with the C++'s messages.
* **State** lives in a heap `Impl` (a `Box`), as the C++ PIMPL: GLFW's
  framebuffer-size callback reaches it through a static (`s_rhi_instance`), so
  `D3d12Rhi` may move. `D3d12Rhi::init` sets the static; `shutdown` clears it.
* **GLFW and Vulkan** are the shared bindings: `ultragui_glfw::sys::glfw` and
  `ultragui_vulkan::sys::vulkan` (its layouts are checked against vulkan.h by
  ultragui_vulkan's layout test, so `tests/layout_test.aki` here covers only
  `sys::d3d12`). The package links `-lvulkan -lglfw` itself and depends on both.
  `RhiConfig::native_window` must be a `GLFWwindow*` (any GLFW window created
  with `GLFW_NO_API`, e.g. `GlfwPlatform::native_handle()`).
* **Linking**: Linux links `-lvkd3d -lvkd3d-utils -lvulkan -lglfw` (the dev shell's
  `LD_LIBRARY_PATH` now includes GLFW). Windows maps to `-ld3d12 -lvulkan-1
  -lglfw3` and passes `akiko check --target x86_64-w64-windows-gnu`, but the C++
  backend has no Windows implementation either (no DXGI swapchain): it needs
  vkd3d's `vkd3d_*` functions, which exist only there.
* **Verification**: `tools/rhi_scene.cc` (C++, against the reference build) and
  `examples/rhi_scene` (aki) draw the same frame through the RHI calls; under
  `aki/tools/xshot.sh` (vkd3d over lavapipe) the two screenshots are
  pixel-identical (ImageMagick `compare -metric AE` is 0), also with
  `SCENE_MODE=stress` (buffer growth, UpdateTexture, destroying textures and
  render targets) and with the aki program loading the shaders from disk
  (`SCENE_SHADER_DIR`). `tests/rhi_test.aki` needs a window and a Vulkan device:
  it skips without a display; `aki/tools/test_xvfb.sh ultragui_d3d12` runs it on lavapipe (slot
  rules, the 256-texture limit, frames with offscreen/video/scissor/dedup, buffer
  growth, swapchain recreation on resize).

On Linux, COM methods and `D3D12SerializeRootSignature` are called through
the generated `csrc/d3d12_abi.c`: vkd3d uses Microsoft's calling convention
on x86-64, while aki extern functions use the platform C ABI. Regenerate the
wrappers and the bridge together with `tools/gen_d3d12.py ... com`, and call
COM methods through the wrappers, never through vtable fields directly.

### UIContext — `ultragui::ui_context`

```aki

loop { let dd = ui.render_draw_data(); ... }                        // or ui.update() with a real Rhi

```

The C++ accessors are public fields (`ui.platform`, `ui.rhi`, `ui.renderer`,
`ui.text_engine`, `ui.input`, `ui.animator`, `ui.script`, `ui.builder`,
`ui.world`, `ui.overlays`, `ui.audio`), so a caller lends them side by side.
Everything else is the C++ API in snake_case (`pump_input`, `find_widget`,
`widget_by_id`, `set_ui_scale`, `set_theme`, `set_frame_reuse`,
`frame_stats`, `queue_offscreen`, `show_overlay`, `load_svg`, `set_audio`).
Differences:

* Each call into widget code builds a WidgetContext from views of the
  fields (text engine, animator, platform, the clock, default font,
  ui scale) beside `self.world`; the C++ widget_ctx_ member is gone.
* Texture seam: draw-data mode keeps the host backend in the renderer
  (`texture_backend()` lends it); legacy mode goes through the Rhi (renderer
  in Rhi-texture mode, an `RhiTextureBackend` per call for SVG/anim loads).
  In draw-data mode TextEngine::FlushAtlas runs against a `NullRhi` (the C++
  calls the linked RHI through a null pointer; the null RHI touches nothing).
* `load_anim(path, w, h): AnimId?` (an index; `anim(id)`/`anim_var(id)`);
  the animations are boxed (`List<Box<VectorAnimation>>`), so their
  addresses hold until shutdown (scripts keep them).
* `set_on_paint(own fn(env: &var PaintEnv<R>) {...})`: the callback gets
  `env.renderer` and `env.rhi` (the C++ arguments) and what a C++ callback
  reads through the `&ui` it captures: `env.world`, `env.ctx` (the widget
  context, for compute_widget_layout / paint_widget_tree), `env.root`,
  `env.time` (`ui.time()`). State a callback keeps goes in a `Mutex` (an
  `own fn` keeps read-only captures; examples/game_overlay's LayoutEngine).
* `add_script_init(own fn(rt: &var S))`: run right after the runtime's init,
  in order (consumed by init); the Lua packages register their bindings
  this way (see "ScriptRuntime").
* `with_host(fn(h: &var ScriptHost))` lends the script host outside a
  script call (what `load_lottie`/`load_video` use); `find_extension(kKey)`
  is the index of the first extension of that type.
* `script_exec(src, name)` is `ui.script().Exec(src, name)` (no timer-clock
  sync, unlike `exec_script`, which is ExecScript).
* The animator's apply/done callbacks are collected and applied after
  Animator::update, in the order made (a done right after its apply).
* **Frame extensions** (LoadLottie/LoadVideo): a package keeps its players in
  a type implementing `scripting::script_host::UiExtension` (`update(env)`,
  `needs_convert()`, `convert(env)`, `shutdown(env)`; `env: &var FrameEnv`
  holds `rhi: DynRhi`, `dt`, `audio`, and `with_textures(fn(tex))` lends the
  texture sink) and registers it with `ui.add_extension(kKey, value): u32`
  (kKey a `ComponentKey<T>` naming the type); `ui.extension_var(kKey, i)` /
  `host.extension_var(kKey, i)` get it back. Update calls every extension's
  `update` after the vector animations, then (if any needs it and
  `acquire_frame` succeeds) `convert`, as the C++ does lottie_anims_ then
  video_players_; register lottie's before video's to keep that order.
  Draw-data frames update no animations (as the C++).
* **ScriptHost** (`ctx.host`, set only for calls that can run a script:
  load_script, exec_script, script_exec, call_handler, the timers, input
  processing and so every widget callback and wired change handler; and
  `with_host`): `anims` with `load_anim`, `anim_var`, `anim_ptr`;
  `find_widget(world, name)` (FindWidgetEntity, through the cache);
  `extensions` with `extension_var`, `find_extension`; and `env: FrameEnv`
  (`rhi: DynRhi`, `audio: &var AudioBackendBox`, the texture sink through
  `env.with_textures(fn(t: (&var DynTextureBackend)?) {...})`, the
  texture_backend_ of the C++). A Lua native reads it from the context the
  runtime was called with (`ultragui_lua` keeps the pointers for the
  duration of a call, as it does the World).
* `register_widget_tree(script, world, root)` is lua_widgets.cc;
  `ui.call_handler(name, w)` is ScriptRuntime::CallHandler with the World,
  context and host; `ui.set_script_click_dispatch()` is the examples' on_click
  lambda (left click on a named widget -> `on_<name>(w)`;
  `set_script_click_dispatch(false)`: any button, the previewer's), run at
  the end of pump_input instead of inside the router (router handlers get no
  World).
* Per-widget updates also lend the ScriptHost: slider and dropdown updates
  can invoke wired change handlers, which need the animation and media hooks
  in both frame modes.

## Fidelity

Reproduce the C++ exactly: float expressions in C++ operation order, the
same rounding, IntroSort (never akikit's sort), from_chars, the same log text
on the same stream. Where C++ behavior is undefined, do what aarch64 does and
say so (`@saturating_cast` for float->int). akiko fuses `a * b + c` into an
fma in every build (language ADR 0221), as clang does for C++ on aarch64
(-ffp-contract=on); where the C++ splits a product and a sum across
statements, keep the product in a local so it rounds alone
(style/transition.aki, cubic_bezier). On x86-64 the C++ build does not fuse,
so bit-exact tables are aarch64's.

### Known C++ quirks kept

- `ugui/backends/ugui_impl_dx11.cc` does not compile as it stands (ULTRAGUI_IMPL_DX11=ON):
  it uses `find()->second`, `end()` and `erase(iterator)` on `ugui::HashMap`, which
  has the pointer-returning `find` and `erase(key)`. The aki port follows the
  evident intent (the semantics of the OpenGL backend's use of the same map);
  `aki/tools/build_d3d11_refs.sh` builds the C++ reference from a patched copy.

- `ParseHexColor` succeeds with what it read when a digit run stops early
  ("#12G456" -> 0x12): only the error code is checked.
- `ArenaScope` resets the whole arena, not to its saved offset; nothing uses
  it, so it is not ported rather than ported wrong.
- `Clamp` (core::math) returns `lo` for `v < lo` even when `lo > hi`;
  `clamp_min_max` is std::clamp. Both exist; use the one the C++ calls.
- `Style::Lerp` leaves align_content, text_transform, text_decoration, cursor
  and pointer_events at `a`'s values.
- Pack functions spill a channel above 1.0 into the next byte, as the C++
  shifts do.
- The shaping cache key compares floats with `==` but hashes their bits
  (`-0.0` and `0.0` may cache twice), as the C++.
- TextEngine's bitmap copy assumes FreeType's positive pitch (the C++ computes
  `row * pitch` unsigned).
- `.ugui` lexer: a byte that starts no token is a one-byte error token in the
  C++; a multi-byte UTF-8 character here is one error token holding the whole
  character (a String cannot hold half of one). A file that is not UTF-8 is
  the error "file is not valid UTF-8" (the C++ parses any bytes); a .uganim
  that is not UTF-8 is a JSON parse error.
- `.ugui` import resolution keeps the C++'s `std::filesystem` imitations
  (ParentPath, JoinPath, LexicallyNormal, WeaklyCanonical) with akikit's
  `real_path`/`path_exists`; Windows uses the same prefix algorithm (the C++
  calls `_fullpath` there).
- NOT kept, on purpose: the C++ `render_anim_frame` caches parsed path layers
  in a thread_local map keyed by the *address* of `AnimLayer::path_data`, so
  a document allocated at a freed document's address renders the old paths.
  The port parses a path layer each frame (what the cache returns when it is
  right); the reference tool leaks its documents so the C++ never hits it.
- VectorAnimation of a looping document with duration 0 spins forever in
  `update` (`while (t >= dur) t -= dur`), as the C++.
- JSON numbers go through C `strtod`, so "-inf", "-nan(12)" and hex floats
  parse as numbers, and `\u0041` reads as "u0041" (no `\u` decoding).
- KeyframeAnimation with a zero duration: the C++ casts inf to int (UB); the
  port saturates.
- SVG: a gradient `<stop>` without `offset` has an uninitialized offset in the
  C++ (the port uses 0); `style=` on a `<stop>` is parsed and dropped.
- SVG: three C++ loops never end on malformed input (text or a stray close
  tag before the root; path data or polyline `points` that stop being
  numbers, which would also grow the path without bound). The port stops at
  the first iteration that consumes no input; every terminating input behaves
  as the C++.
- SVG: attribute values are C strings, so a value is cut at its first NUL and
  numbers are libc's `strtof` (viewBox, width/height, path data) or
  `atof`-through-`strtod` rounded to f32 (everything else), as in the C++;
  `sys::c_text` calls libc for both so the values cannot differ.
- `VideoPlayer::Load(rhi, path, AudioBackend* audio)` only tests `audio` for
  non-null; the audio plays through the bridge's own `ma_device`, not through
  the backend. The port takes `(&DynAudioBackend)?` and tests it for `some`.
- pl_mpeg's video callback uploads every decoded frame to the RHI inside
  `plm_decode`/`plm_seek`. The port copies each frame's planes in the
  callback and uploads them in order when the call returns (no RHI in
  reach of a C callback): same RHI calls, same contents, uploaded at the end
  of the call.
- `LottieAnimation` computes `frameAtPos` itself (rlottie's formula in
  `double`): the C API's `lottie_animation_get_frame_at_pos` narrows the
  position to `float` and can pick a different frame than the C++ call.
- The audio bridge's `volume`/`muted` are plain fields read by the audio
  thread while the main thread writes them, as in the C++.
- Renderer2D::DrawTextLayout computes a slack against `max_width` and throws
  it away: every line is drawn left-aligned, whatever max_width says.
- Renderer2D's gradient cache keys collide as the C++ ones do (the
  multi-stop hash XORs shifted fields; a collision reuses the texture).
- Widget kinds, all as the C++ does them: checkbox and radio measure their
  box from the unscaled font size (1.2x) but draw it at 1.0x of the scaled
  one; the scroll view draws without ui scale; the context menu's click
  hit-tests rows with the unscaled style while its draw uses the scaled one;
  the dropdown measures with 12 px side padding but draws with 8, and dims
  the label only when `selected < 0`; the dropdown and scroll-view hit tests
  skip the hidden/collapsed check of hit_test's default path;
  show_context_menu_at and show_message_box write the style without
  mark_dirty; set_rich_text_font marks nothing dirty; the radio and slider
  setters do not check the kind; text-input Up applies the history text
  unless it is empty and equal to the current text; Ctrl+V does not reset
  the caret blink; set_dropdown_selected clamps through f32.
- VulkanRhi: draw_text_triangles advances the text write positions a second
  time after its draw (it only wastes buffer space); the swapchain always uses
  FIFO (`choose_present_mode(modes, true)`: RhiConfig::vsync is ignored), and
  so is RhiConfig::embedded, as vulkan_rhi.cc does.
- GlfwPlatform::set_cursor's standard cursors are process statics created on
  first use and never destroyed (they outlive glfwTerminate), as the C++
  function-local statics are.
- D3D12 RHI: growing an upload buffer (more than 16384 vertices or 32768
  indices in a frame) frees the old buffer, which draws recorded earlier in the
  same frame still reference (use after free on execute): only a frame whose
  first draw grows is safe (the aki scene and test warm both ring slots up that
  way). The new buffer is not a copy of the old, so draws before the growth lose
  their data too.
- D3D12 RHI: `filter` of create_texture, `RhiConfig::validation` and `embedded`
  are unused (static samplers: s0 linear, s1 nearest for text); the SRV index is
  the texture handle (256 textures, the white fallback in slot 0); every
  create/update/destroy waits for the GPU with a spin loop; `shutdown` does not
  clear what it released, so it runs once; EndFrame presents through
  `vkd3d_acquire_vk_queue` and recreates the swapchain after a suboptimal or
  resized present.

- Lua runtime: `UpdateTimers` runs a tween's `ugui.set` through the global
  `ugui` table without a protected lookup (a script that replaces `ugui`
  makes the next update abort in Lua's panic handler, both sides); a tween
  whose duration is 0 computes `0/0` at its start time (NaN -> channel 0 for
  colors, as `static_cast<int>` gives on aarch64); `ugui.after` with a
  negative delay fires on the next update; `UnregisterWidget` erases by name,
  so it drops whichever widget holds that name; `ugui.anim_*`/`lottie_*`/
  `video_*` with a nil handle skip their argument checks (`if (a)
  a->set_speed(luaL_checknumber(...))`), but `*_attach` checks the name
  first; `ugui.set` of a property it does not know (border-width,
  border-color) re-applies the style unchanged and still clears the
  animation style. Lua 5.4 seeds `math.random` per state from the clock: the
  tests call `math.randomseed(42)` on both sides.
- Lua runtime shutdown keeps its timers, tweens and timer clock, as
  `ScriptRuntime::Shutdown` does: reinitializing the same runtime can reuse
  stale registry references, fire a new callback early and then invalidate
  its reference (reproduced in the C++). Clear timers and tweens before
  shutdown when reusing a runtime.
- TextEngine::Shutdown leaves `atlas_texture_` unchanged: after an atlas
  upload, reinitializing the same engine updates the destroyed texture
  handle on FlushAtlas and destroys it again on the next Shutdown
  (reproduced in the C++).
- UIContext's frame start returns after a failed acquisition or frame
  (ui_context.cc:469, :491) without resetting `input_pumped_this_frame_`, so
  input polling stays suppressed until an update reaches its normal end.
- Backends: destroying a texture drops its descriptor set without returning
  it to the pool (Vulkan, vulkan_rhi.cc / ugui_impl_vulkan.cc), so heavy
  texture churn can exhaust the pool; D3D12 RTV indices only grow, and
  swapchain recreation resets the allocator while surviving render targets
  keep their indices (d3d12_rhi.cc:796, :1827); Vulkan's present semaphores
  cover the first swapchain's image count (at most 8) and are not added when
  a recreated swapchain has more images (vulkan_rhi.cc:349, :740).
- UIContext::DrawTooltip clamps against `rhi_.display_size()`, which the
  null RHI (draw-data mode) reports as 0x0: every draw-data tooltip is moved
  left of and above its target. Kept (the golden scenarios depend on it).
- UIContext's tooltip delay compares accumulated f64 clock differences with
  `>= 0.5`: steps of 0.1+0.3+0.2... can land a hair under it, as in the C++.
- FrameReuse::kVerify hashes DrawCmd's padding bytes in the C++ (indeterminate);
  the port feeds the C layout with zeros there (the hash only ever compares
  with itself).
- UIContext::Init ignores the script runtime's Init result, as the C++.
- Lua 5.4 seeds `math.random` per state from the clock and addresses: the
  golden runners and `tools/xshot_fixed.sh` seed it (42) so scripts that
  draw random numbers replay; the examples themselves do not, as the C++.

### Shape differences (not behavior)

- **VectorAnimation does not store its TextureBackend.** `load(backend, path,
  w, h)`, `load_data(backend, json, w, h)`, `update(backend, dt)` and
  `unload(backend)` take it as `(&var T)?` for any `T: TextureBackend` (a
  `DynTextureBackend`, a `TextureBackendBox`, an `RhiTextureBackend`; `none`
  is the C++ `nullptr`), because a stored borrow would pin UIContext, which
  owns both. The destructor therefore cannot destroy the texture: call
  `unload(backend)` first. Pass the same backend each time.
- **idl::parser AST**: `UguiNode::type` is `type_`; the nested C++ types are
  module-level: `UguiStateBlock`, `UguiKeyframeBlock` (+ `UguiKeyframeStop`),
  `UguiMediaQuery`, `UguiStyleClass`, `UguiComponent`; `UguiDocument` and
  `ParseError` as in the C++. Entry points: `parse_ugui(source: str,
  filename: str, doc, errors): bool` and `parse_ugui_file(path, doc, errors)`;
  every AST type is `Clone`. Property maps are `HashMap<String, String>`
  (walk them with `sorted_entries`, as the C++ builder does).
- **anim**: `AnimDocument::loop` is `looping`; `parse_anim_data(json: str,
  doc)` and `parse_anim_file(path, doc)` take text (a non-UTF-8 file is a
  parse error); `json::JsonValue::type` is `kind`; `evaluate_layer` returns
  the `EvaluatedLayer`; `render_anim_frame(doc, time, pixels: &var [u8], w,
  h)` builds its svg Document per call and parses path layers each frame
  (the C++ caches by the address of `path_data`).

- SVG: `LoadSvg*` return `SvgImage?`, `ParseSvg` returns `Document?`,
  `Rasterize` writes into a `&var [u8]`, `LoadSvgTexture` takes `(&var T)?`
  for any `TextureBackend` (a `DynTextureBackend` is one); the rasterizer's
  `thread_local` scratch vectors are locals. `w * h * 4` is a `usize`.

- No thread-local active registry; World passed explicitly.
- WidgetContext passed, not pointed to; `current_time` is a value.
- TextEngine takes the dpi scale and the Rhi as arguments; runs share glyphs.
- SetWidgetVTable (no users) and run-time vtable install are gone.
- Calls into a TextEngine before `init()` are no-ops where the C++ crashes.
- Widget creators and setters take the World first (`create_button(world, id)`,
  `set_text(world, e, "...")`); those that change state through
  set_widget_state take the context too (`set_checked(world, ctx, e, v)`,
  `set_radio_selected`, `set_toggle_on`). String parameters are `str`,
  `Vector<String>` parameters slices (`set_dropdown_options(world, e,
  list.as_slice())`), String results owned copies.
- Widget callbacks get a CallbackEnv (above), and may replace or destroy
  their own widget safely.
- A text-input char event whose code point has no UTF-8 form (a surrogate,
  above U+10FFFF) inserts nothing: aki's String is always valid UTF-8. The
  C++ inserts the bytes its encoder makes.
- Modal and message box build the backdrop and button row as CreatePanel(0)
  written out (a widget tagged Panel), not through widgets::panel.
- VulkanRhi / GlfwPlatform keep their Impl in a `Box` (GLFW's user pointer
  and the RHI's resize callback hold its address); texture `pixels` shorter
  than the texture (the C++ nullptr, a crash there) upload zeros for the rest;
  VulkanRhi's find_memory_type stops where the C++ asserts;
  GlfwPlatform::clipboard_text is "" where GLFW returns NULL or non-UTF-8.
- ugui_impl_vulkan's global backend is a `VulkanBackend` value, and is
  itself the TextureBackend.
- The audio Lua natives point at UIContext's AudioBackendBox field, so a
  `set_audio` after init reaches the scripts (the C++ binds `*audio_` at
  Init, and its scripts keep the backend they started with).
- The examples' `on_<name>` click handlers run where they can reach the
  World: after `input.process` returns, not inside the router. (embed_*'s
  button lambdas stay router handlers: they compare the clicked widget with
  the btn_hello found once instead of reading its name.)
- LuaRuntime: text from Lua becomes a String (`check_string`, the paths and
  names hooks get, `set_text`/`set_button_label` values, tween widget and
  property names) with each byte that is not UTF-8 replaced by U+FFFD; the
  C++ keeps the bytes. Output (`ugui.log`, the runtime's stderr lines) prints
  the bytes as Lua holds them. A runtime used before `init()` or after
  `shutdown()` does nothing and reports failure where the C++ dereferences a
  null lua_State; dropping a LuaRuntime closes its state (the C++ destructor
  leaks it). Lua memory errors inside natives still longjmp through aki
  frames (only the argument checks were restructured).

## Pitfalls and compiler workarounds (akiko 0.7.0)

- **An `extern` function is not a function value** ("unsafe or extern"): to hand
  C a callback that wraps a C function (`pfn_signal_event = vkd3d_signal_event`),
  define an `extern fn` with a body that calls it and pass `@c_fn(that)`.
- **`&raw x` needs a place**: a `static let` is one (`&raw kIidDevice`), a
  `comptime let` is not. Casts to raw pointers (`raw as *var T`, `p as *const u8`)
  need `unsafe` even inside an expression: `unsafe (raw as *var T)`.
- **Field-style names that are keywords** (`type`, `end`) get a suffix or another
  word (`heap_type`, `type_`); `extern struct`s default every field to zero so
  `X {}` works, `extern union`s are built with one member (`U { b: 0 }`).
- A COM out-parameter (`void** ppv`): a local `var raw: *var u8 = null;`, pass
  `&raw var raw`, then `unsafe (raw as *var ID3D12Foo)`.

- **`static fn` types cannot name lifetimes**, so a call through a
  `static fn(&var World, &var WidgetContext, ...)` value fails ("cannot store
  a view of 'world' through 'ctx'"). Dispatch with `match` and direct calls
  (widget_vtable) or keep only one lifetime-carrying view per signature.
- **No function-local statics**, and **static capability methods cannot be
  called through a type parameter** (`T::slot()` is "unknown module T"). Hence
  ComponentKey values instead of a per-type id.
- **`let _ = f()` where `f` returns a view** is "cannot move out of the view":
  write the call as a statement (`world.add(k, e, v);`).
- **A temporary is not a `var` place**: `f(boxed.as_dyn())` for a
  `var x&: DynX` parameter fails; bind it (`var d = boxed.as_dyn(); f(d);`).
- **A closure cannot capture a field of `s` while another field of `s` is
  lent to the call**: bind views of both fields first
  (`var w& = ui.world; var a& = ui.animator; a.update(t, fn(...) { ... w ... });`).
- **`push_c8` stops on a byte >= 0x80** (a String is UTF-8): to build text from
  source bytes, copy runs between ASCII delimiters with `push_str(s[a..b])`.
- **A ternary in an f-string hole needs parentheses and typed literals**:
  `{(ok ? 1i32 : 0i32)}`.
- **`if (var x& = list.at_var(i))` on a `List<T?>`** fails ("needs a place");
  use the index place `list[i]`.
- **`&raw` takes a place, not a parameter's target**: bind the view first
  (`var target& = object; &raw var target`), see core::erased.
- **Struct literal of a type with private fields** works only in that type's
  own methods: give it a private `Type::from_parts(...)` and call that.
- `[u8; N] as bytes` does not cast; slice first (`arr[..] as bytes`). `_` is
  not a type placeholder in casts.
- A view of a slice is already a view: `let out = list.as_slice_var()[a..b];`
  not `var out& = ...`.
- Type arguments of generic calls with only literal arguments need a suffix
  (`min(3i32, 2)`).
- `null` is a keyword (no method named `null`).
- **`for (var b in list.iter_var())` binds a copy**: writes to `b` are lost.
  Write through a view (`for (var b& in list)`) or the index (`list[j].f = x`).
- Integer `+ - *` stop on overflow; hashes need the wrapping forms
  (`h = h *% 1099511628211`). Shifts drop shifted-out bits unchecked.
- **A call through a function value with two view arguments** that name no
  common lifetime (`&var World`, `&var WidgetContext<'a>`) is "cannot store a
  view of 'world' through 'ctx'", and so is a `str` beside a view-holding
  argument. Pass one struct that holds both views (CallbackEnv), and text
  owned (`String`).
- **Taking a value out of a component**: `replace(c.slot, none)`, or a
  `swap` through a `let c& = world.get_var(..) else {..}` binding, keeps the
  World borrowed as long as the taken value lives. Swap into a local inside
  `if (var c& = world.get_var(k, e)) { swap(c.slot, local); }` and the borrow
  ends with the block.
- **No generic capabilities and no generic capability methods**: `capability
  X<R>` does not parse and `fn m<R: Rhi>(...)` in a capability is "undeclared
  name R". Erase the type instead (DynRhi) or make the generic part a struct.
- **Calling an `own fn` stored in `self` with views of `self`'s other fields**
  makes the compiler assume the callback keeps them ("cannot store a view of
  'self' into 'self'"). Swap it out (`var slot: F? = none; swap(self.cb, slot);
  let handler = slot else {...}`), call it in a block with one struct of views
  (PaintEnv, CallbackEnv), then put it back (UIContext::run_paint_callback).
- **Two closures passed to one call cannot both capture the same `var` view**
  ("cannot pass 'st' twice to one call"): give each its own list and share an
  `Atomic` counter by `let` capture to recover the interleaving
  (UIContext::step_animator).
- Module import cycles are fine (widget_context -> script_host -> widget ->
  widget_context).
- C `long` differs per OS: use `CLong`/`CULong` from `ultragui::sys::c_long`
  (one module per OS under `os/`; each OS table in aki.toml needs its own
  directory, they cannot share one). Check Windows layouts with
  `akiko check --target x86_64-w64-windows-gnu`.
- akiko adds no runpath for C libraries: the dev shell's `LD_LIBRARY_PATH`
  carries libstdc++, FreeType and HarfBuzz; a new C dependency needs its lib
  directory there too (flake.nix shellHook).
- **Float fusion is per expression, and matches clang's on aarch64** for the
  SVG rasterizer (`a*b + c*d`, `a*b - c*d - e*f`, `x*y + z*w + e`: 19 of the
  62 corpus renders change when the C++ is built with `-ffp-contract=off`, and
  all 62 match the default build). Vec2/Transform operator methods never
  fuse, as the C++ operators do not: write `p + n.scale(w)` where the C++
  writes `p + n * w`.
- `match` patterns take integer literals, not `'x' as u8`: match on the code
  (`109 => { // 'm'`).
- `fn` literals as `less`/`erase_if` predicates may capture locals
  (`fn(a&: usize, b&: usize): bool => edges[a].y0 < edges[b].y0`).
  carries libstdc++, FreeType, HarfBuzz, GLFW and the Vulkan loader; a new
  C dependency needs its lib directory there too (flake.nix shellHook).
- **No fn-pointer casts**: `@bit_cast` refuses `extern fn` types; turn a
  `PFN_vkVoidFunction` into the real type with
  `var f = p; let g = unsafe @read(&raw var f as *const RealFn);`
  (vulkan_rhi, the debug-messenger functions).
- `import {x as y} from a::b` needs `a::b` to be a module: a directory is not
  one (`import {vulkan as vk} from ultragui_vulkan::sys` fails). Use
  `import * from ultragui_vulkan::sys::vulkan;` for a whole binding.
- akiko does not check a file's `module` line against its path; a typo there
  shows up only as "unknown module" at the importer.
- `List::filled` does not exist: `filled(n, v)` is a free function of
  akikit::containers::list. `arguments()` (akikit::process::command_line)
  leaves out the program path. `none` and `module` are keywords.
- `extern struct` fields may have defaults (the Vulkan binding relies on it).
- C sources compiled through `c_sources` warn about `_FORTIFY_SOURCE` without
  `-O` (rlottie, pl_mpeg, miniaudio; yoga did before the flex engine replaced
  it); `-Wno-#warnings` in `c_flags` silences it.
- **Private fields of a module-private struct are private to its methods**:
  helper structs used by free functions in the same file (`SoundSlot`, `Impl`
  in ugui_impl_miniaudio) need `pub var` fields.
- **`unowned` goes after `pub`**: `pub unowned var device: *var T`.
- **Multi-line text is `r"""` ... `"""`** (raw, closer on its own line); a
  plain `"` cannot span lines. Handy for JSON in tests.
- **`[build.implement]` flags**: one argument per flag, and an argument not
  starting with `-` is a macro: `"-includestdio.h"`, not `"-include", "stdio.h"`.
- **`@slice(p, n)` / `@slice_var` results are already views**: `let s = ...`,
  not `let s& = ...`.
- **A struct can hold an `extern fn` value** (`pull: extern fn(*var u8, *var f32, u32): ()`
  in an extern signature), made with `@c_fn(callback_name)`; the callback's user
  pointer to a heap object comes from `Box::as_ptr` (stable while the Box lives).
- **`switch` cases are blocks**: `case 1: { return t * t; }` and
  `default: { ... }`, not C's fallthrough labels.
- **An error type that holds a `str`** makes `try` results look like views:
  `fn f(self&): String ! E` with `union E { Message(str) }` fails with "cannot
  return a view into local". Keep error unions to plain data (a static C
  string as `*const c_char`).
- **An `extern fn` takes no union** (only integers, floats, bool, raw
  pointers, enums, C structs): pass a union's parts to an `extern(longjmp)`
  raiser (ultragui_lua::lua_runtime `raise`).
- A `lua_CFunction` is an `extern(longjmp) fn` with a body, passed with
  `@c_fn`; keep it to a call of a plain aki function that returns `T !
  LuaRaise` and a raise of the error after that call has returned (the
  pattern in lua_runtime: run_builtin + raise).
- Run tests from the package dir; data files are found with `@package_dir()`
  (`f"{@package_dir()}/../../examples/demo.mpg"`).
